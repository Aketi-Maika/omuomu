# 写真展「写っているのは、だれ？」

NAS にある写真をフラッシュカードのように 1 枚ずつ見せ、名簿から「写っている人」を選んでもらうサイトです。
GitHub Pages で公開し、写真・名簿は暗号化して置き、Google アカウント（許可したドメイン）でログインした人だけが見られます。

```
NAS の写真フォルダー ─┐
写真登録.xlsx（名簿）─┼─▶ omuomu-gallery（この PC・Rust）── 縮小・暗号化 ──▶ web/public/data ──▶ GitHub Pages
                       │        └ 管理画面 http://127.0.0.1:8787（NAS のパス・Google ログイン等を設定）
                       │
参加者のブラウザ ◀──── Vue 3 + Rust(WASM) で復号して表示 ──▶ 回答を Google スプレッドシートへ
```

| 画面 | 内容 |
| --- | --- |
| 入口 `#/` | **Google アカウントでログイン**（許可したドメインのみ）。入場はメールアドレス付きで記録 |
| カード `#/cards` | 写真がランダムに 1 枚ずつ出る。PC はカードの右に名簿、スマホは「次へ」で名簿画面へ。<br>不明／退会／教職員は名簿に関係なく常に選べる。回答が 10 件以上の写真は出にくくなる（約 1/30） |
| 管理室 `#/admin` | 管理者として登録した Google アカウントのみ。人物で絞り込み（AND/OR・得票率）→ ZIP、入力状況、**ログ**（誰が・いつ・何をしたか、CSV 出力） |
| 設定（管理室の中） | この PC で管理ツールを起動したときだけ表示。NAS のパス、名簿、Google ログイン、表示文言、出やすさ、構築・公開 |

## 必要なもの（初回のみ）

- Rust（`rustup`）と `wasm32-unknown-unknown` ターゲット、`wasm-pack`
  ```
  rustup target add wasm32-unknown-unknown
  cargo install wasm-pack --locked
  ```
- Node.js 20 以上
- Git（GitHub にログイン済み）

## 使い方

### 1. 画面をビルド（初回と、プログラムを更新したとき）

```
cd 写真\web
npm install
npm run wasm
npm run build
```

### 2. 管理ツールを起動して設定

```
cd 写真
cargo run --release
```

ブラウザで管理画面（`http://127.0.0.1:8787/#/admin`）が開くので「設定」で次を入力して保存します。

- **写真の登録元（NAS）**: `\\NAS名\共有\写真\2023` や `Z:\写真` など。複数指定可、サブフォルダーも読み込みます（JPEG / PNG）
- **名簿**: `..\写真登録.xlsx`（B 列=名前、C 列=部署。名前の行に貼った写真は「登録済み」として管理室の判定に使います）
- **Google ログイン**: OAuth クライアント ID、許可するドメイン、管理者のメールアドレス、Apps Script の URL（下の「Google ログインの準備」）
- 未設定のままでも、この PC では入口の「この PC で確認」から表示を確かめられます（記録はその端末内だけ）

設定は `写真\gallery.config.json` に保存されます（写真の鍵を含むので git には入りません）。

### 3. 構築 → 公開

設定画面の **「保存して構築」** で NAS の写真を長辺 1600px に縮小し、EXIF（位置情報など）を消して暗号化します。
2 回目以降は増えた写真だけ処理します。**「GitHub に公開」** で暗号化済みデータ（`web/public/data`）だけを commit / push します。

push されると GitHub Actions（`.github/workflows/photo-pages.yml`）が画面をビルドして GitHub Pages に公開します。

> 初回だけ、このフォルダーのプログラム一式と `.github/workflows/photo-pages.yml` を commit / push し、
> GitHub のリポジトリ設定 → Pages → Source を **GitHub Actions** にしてください。
> `2023` ブランチから公開する場合は Settings → Environments → github-pages の許可ブランチに `2023` を追加します。

## Google ログインの準備

1. **OAuth クライアント ID を作る**（Google Cloud コンソール）
   - プロジェクトを作成 →「API とサービス」→「OAuth 同意画面」を設定（ユーザーの種類は、許可するドメインが Google Workspace なら「内部」が安全）
   - 「認証情報」→「認証情報を作成」→「OAuth クライアント ID」→ 種類「ウェブ アプリケーション」
   - 「承認済みの JavaScript 生成元」に `https://<ユーザー名>.github.io` と `http://localhost:8787` を追加
   - 表示されたクライアント ID を管理画面の「OAuth クライアント ID」に貼る
2. 管理画面で「許可するドメイン」と「管理者のメールアドレス」を入れて保存
3. **Apps Script を用意する**
   - Google スプレッドシートを新規作成 →［拡張機能］→［Apps Script］に `apps-script/Code.gs` を貼り付けて保存
   - 管理画面の「Apps Script に貼る設定を表示」→ コピー → エディタに貼り付けて `setupProperties` を 1 回実行（権限の確認が出たら許可）→ その関数は消してよい
   - ［デプロイ］→［新しいデプロイ］→ ウェブアプリ（実行ユーザー: 自分、アクセス: 全員）→ URL を管理画面に貼る
4. 管理画面で「保存して構築」→「GitHub に公開」

ドメイン・管理者・鍵を変えたときは、手順 3 の `setupProperties` をもう一度実行します（再デプロイは不要）。

### 記録されるもの

| シート | 内容 |
| --- | --- |
| `responses` | 写っている人の回答（日時・写真・選んだ人・不明/退会/教職員・**メール**・氏名）。1 回 1 行で追記 |
| `audit` | 入場（管理者かどうか）、管理室への入室・タブ移動、人物での絞り込み、ZIP ダウンロード（どの写真か）、原寸の書き出し |

メールアドレスは、ブラウザが申告した名前ではなく、Apps Script が Google のログイン証明（ID トークン）を検証して得たものです。
管理室の「ログ」タブで検索・CSV 出力できます。

## セキュリティについて

- 写真・名簿は 32 バイトのランダムな鍵で AES-256-GCM 暗号化しています。公開リポジトリに置いても、鍵なしでは写真も名前も見られません。
- 鍵は PC の `gallery.config.json` と Apps Script のスクリプトプロパティにだけあり、Apps Script は **Google ログインを検証して許可したアカウントにだけ** 鍵を渡します。
- 平文で公開されるのはタイトル・会期などの表示文言、写真の枚数、Google のクライアント ID、Apps Script の URL です（`public.json`）。
- 一度入場した人は鍵を受け取っているので、その人が鍵を書き出して他人に渡すことは技術的には防げません。心配なときは「鍵を作り直す」→ 構築 → 公開 → `setupProperties` を再実行すると、古い鍵では開けなくなります（git の履歴には古い暗号データが残ります）。
- 操作ログのうち、入場と回答はサーバー側（Apps Script）で記録します。管理室での絞り込み・ダウンロードはブラウザから送るため、意図的に通信を止められると記録されません。
- **元の写真（JPEG）や `写真登録.xlsx` をリポジトリに commit しないでください。** 公開リポジトリだと誰でも見られます。

## フォルダー構成

```
写真/
├─ crates/core     暗号・抽選（PC と WASM で共通）
├─ crates/wasm     ブラウザ用（復号・ZIP 作成・重み付き抽選）
├─ crates/admin    omuomu-gallery（NAS 読み込み・暗号化・ローカル管理画面・公開）
├─ web/            Vue 3 + Vite
│   └─ public/data 暗号化済み公開データ（構築で生成）
└─ apps-script/    スプレッドシート保存用
```

## 開発

```
cargo test                       # Rust のテスト
cd web && npm run dev            # 画面の開発サーバー（API は 127.0.0.1:8787 の管理ツールに中継）
```
