# 写真展「写っているのは、だれ？」

NAS にある写真をフラッシュカードのように 1 枚ずつ見せ、名簿から「写っている人」を選んでもらうサイトです。
画面は GitHub Pages に置き、写真・名簿・回答は NAS の外に出しません。

```
GitHub Pages（画面のプログラムと表示用の文言だけ）
        │ Google でログイン
        ▼
NAS の公開 API（https。Tailscale Funnel / Cloudflare Tunnel 経由）
        ├─ Google のログイン証明を確かめ、許可した組織（hd）と管理者だけを通す（毎回の通信で確認）
        ├─ 写真を 1 枚ずつ返す・名簿を返す
        └─ 回答・操作ログを保存 ──(任意)──▶ Google スプレッドシートに写す

NAS の管理画面（NAS の中だけ。PC からは SSH トンネル）
        └─ 写真フォルダー・名簿・ログインの設定 → 構築 → GitHub に公開（public.json だけ）
```

| 画面 | 内容 |
| --- | --- |
| 入口 `#/` | Google アカウントでログイン（許可した組織のアカウントと管理者のみ） |
| カード `#/cards` | 写真がランダムに 1 枚ずつ出る。PC はカードの右に名簿、スマホは「次へ」で名簿画面へ。<br>不明／退会／教職員は常に選べる。回答が 10 件以上の写真は出にくくなる（約 1/30） |
| 管理室 `#/admin` | 管理者のみ。人物で絞り込み（AND/OR・得票率）→ ZIP（NAS が作成・記録）、入力状況、ログ（CSV 出力） |
| 設定（管理室の中） | 管理ツールの中で開いたときだけ。写真フォルダー・名簿・Google ログイン・公開 API・表示文言・構築・公開 |

## 使い方

NAS の準備は [`nas/README.md`](nas/README.md) を参照してください（ディスク・共有フォルダー・常駐・トンネル）。

### 画面をビルドする（プログラムを変えたとき）

```
cd 写真\web
npm install
npm run wasm
npm run build
```

Windows でも `cd 写真` → `cargo run --release` で管理ツールを動かして表示を確認できます（入口の「管理ツールで確認」）。

## Google ログインの準備

1. Google Cloud コンソール →「Google Auth Platform」
   - 「対象」：組織（Google Workspace）のアカウントだけにするなら「内部」
   - 「クライアント」→ 作成 → 種類「ウェブ アプリケーション」
   - 「承認済みの JavaScript 生成元」に `https://<ユーザー名>.github.io` と `http://localhost:8787`
   - クライアント ID を管理画面の「OAuth クライアント ID」に貼る（クライアント シークレットは使いません）
2. 管理画面で「許可する組織のドメイン」「管理者のメールアドレス」を入れて保存
3. 公開 API の URL（トンネルのアドレス）を入れて「接続を確認」→「保存して構築」→「GitHub に公開」

## スプレッドシートへの写し（任意）

1. Google スプレッドシートを新規作成 →［拡張機能］→［Apps Script］に `apps-script/Code.gs` を貼り付けて保存
2. 管理画面で合言葉を「生成」→「Apps Script に貼る設定を表示」→ コピーしてエディタで `setupProperties` を 1 回実行
3. ［デプロイ］→ ウェブアプリ（実行ユーザー: 自分、アクセス: 全員）→ URL を管理画面に貼って保存

NAS が 30 秒ごとに `responses`（回答）と `audit`（入場・入場できず・管理室の操作・ZIP ダウンロード）を追記します。

## 記録されるもの

| 記録 | 内容 |
| --- | --- |
| 回答 | 日時・写真・選んだ人（NAS の名簿と照合したもの）・不明/退会/教職員・**メールアドレス**・氏名 |
| 入場 / 入場できず | ログインしたアカウント・管理者かどうか |
| 管理室 | 入室・タブ移動・人物での絞り込み・**ZIP ダウンロード（どの写真か。NAS 側で記録）**・原寸の書き出し |

メールアドレスは、NAS が Google のログイン証明（ID トークン）を Google に問い合わせて確かめたものです。

## セキュリティについて

- **写真・名簿は配りません。** NAS がログインを毎回確かめて 1 枚ずつ返します。鍵を配る方式ではないので、
  入場を止めた（ドメインから外した・「入場を止めるアカウント」に入れた）人は、次の通信から写真も名簿も受け取れません。
  ただし、それまでに画面に表示された写真を保存・撮影されることは防げません。
- 許可するドメインは、メールアドレスの末尾ではなく Google Workspace の組織（ID トークンの `hd`）で判定します。
  組織外で同じドメインのアドレスを使って作った個人アカウントは入れません（`gmail.com` を許可した場合だけ個人の Gmail を受け付けます）。
- ログイン状態は NAS の秘密で署名したトークン（既定 8 時間）で、書き換えると NAS が受け付けません。
- 公開 API は、許可したサイト（GitHub Pages）からの呼び出しだけを受け付けます（CORS）。管理用の操作は持っていません。
- NAS の管理画面は NAS の中だけで動かし、PC からは SSH トンネルで開きます（`nas/README.md`）。
- GitHub に置くのは `web/public/data/public.json`（タイトル・会期・写真の枚数・Google のクライアント ID・公開 API の URL）だけです。
- **元の写真（JPEG）・`写真登録.xlsx`・`gallery.config.json`・`.private/` をリポジトリに入れないでください**（`.gitignore` で除外済み）。

## フォルダー構成

```
写真/
├─ crates/core     抽選・パスワード変換（PC/NAS と WASM で共通）
├─ crates/wasm     ブラウザ用（重み付き抽選）
├─ crates/admin    omuomu-gallery（写真の読み込み・公開 API・管理画面・公開）
├─ web/            Vue 3 + Vite（GitHub Pages に置く画面）
│   └─ public/data public.json（表示用の文言と接続先）
├─ apps-script/    スプレッドシートへの写し
└─ nas/            NAS 用のスクリプトと手順書
```

## 開発

```
cargo test                       # Rust のテスト
cd web && npm run dev            # 画面の開発サーバー（API は 127.0.0.1:8787 の管理ツールに中継）
```
